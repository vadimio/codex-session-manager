# Contributing

Contributions are welcome! Bug reports, UX ideas, documentation improvements,
tests, and code all help make managing Codex history less frustrating.

For a substantial change, open an issue first so we can agree on the behavior
before you spend time implementing it. For a small fix, a pull request is fine.

## Send a change

1. Fork the repository and create a branch for your change
2. Keep the change focused and explain the problem it solves
3. Add or update tests; use only fictional conversations and temporary Codex homes
4. Run the checks in the [development guide](docs/development.md#run-the-checks)
5. Open a pull request with a short description, test results, and synthetic screenshots for UI changes

Never submit real sessions, memories, databases, credentials, or private project
information. Destructive session operations must continue to use native Codex
commands, not direct edits to resumable JSONL. Report vulnerabilities through
the [private security process](SECURITY.md), not a public issue.

All changes require maintainer review and passing checks before merging.
Workflows from external contributors also require approval; a pending workflow
does not mean your contribution has been rejected. Passing tests alone does not
mean a contribution will be accepted.
